# fix461 — Compact List Content rows

Replace the expanded submission cards with four aligned columns: employee, status, List Content and last update. Show the latest text once, clamped to two lines; the text itself can expand in place with click, Enter or Space. Only records with stored prior versions show a small history toggle. History starts collapsed, expands beneath the corresponding text, and retains its open state across refreshes. Empty rows contain a dash instead of an empty history card.

Remove the duplicate read-text button, repeated current-text heading, repeated dates and explanatory table footer. Employees keep a pencil action for their own submission; the inline editor contains the editable text once. Existing master-role restrictions, ETag save function, online history schema, offline retry and draft/focus retention remain in place. No database rules or production work records are changed by this release.

Validation: 117/117 regression scripts. Seven isolated browser suites cover navigation, Audit persistence, review rounds, cross-device sync, auth recovery, conflict recovery and the compact List Content flow. Extended checks verify the four columns, no duplicate viewer, no empty history toggle, collapsed/expanded history persistence, keyboard text expansion, compact row height, own-editor availability, online save/reload, offline retry and separate HOOK destinations. Browser screenshots of both compact states were reviewed. Deployment verification includes public asset hashes, successful GitHub checks and signed-in production UI; tests do not claim that every physical employee device is currently online.
