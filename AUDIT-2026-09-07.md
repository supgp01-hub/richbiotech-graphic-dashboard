# Reliability audit — 7 September 2026

## Confirmed defects repaired

- A GET started before a save could return after the PUT completed. The pending queue had already removed the write, so its overlay accepted the obsolete GET and overwrote the new record. Each in-flight read now retains relevant writes until its callback finishes. Subsequent reads continue accepting colleagues' changes.
- A failed collection GET with only a pending child write was reported as successful with an incomplete collection. Read errors now remain errors unless a queued parent or exact snapshot covers the requested data.
- List Facebook's credential drawer rebuilt the account form when opened, closed, or cancelled, losing unrelated unsaved fields. Drawer visibility now changes without replacing the form. Cancelling credentials resets only those fields.
- The account form now binds saves and deletes to its displayed account rather than a separately changing list selection. A completed save no longer clears edits typed while that save was pending.
- Restoring a PIN session discarded the stored session on any network error. Transient failures now retry without deleting it; explicitly expired or revoked refresh tokens still require login. Explicit logout cancels retry timers.

- Updated suite: 90 tests passed, including three new behavioral regression files.
- Live build before deployment: fix389. Navigation opened Home, Product brand, Graphic team, orders, Content Tracker, commissions, audit deductions, Facebook Pages, List Facebook, ID cards, leave calendar, and Social Media without captured console errors during the smoke check.

- Changed asset query versions and service-worker cache name ensure the repaired scripts are fetched after reload.

## Limits and remaining verification

- The employee's exact failing page/button has not yet been identified. The repairs above address reproducible code defects, not a confirmed reconstruction of that employee incident.
- Live checks used an existing Supervisor session. Employee-role write permissions, every dynamic row button, real uploads, destructive actions, and simultaneous physical employee devices were not exhaustively exercised.
- No real employee record was deliberately created, edited, or deleted as a test. Production write/read-back under an affected employee login remains to be verified.
- The Facebook source freshness indicators showed older sheet snapshots. A connected Firebase status alone does not prove a fresh external sheet import.
- This change does not recover records already absent from both the server and a device's durable queue; recovery requires inspecting the affected device or a backup.

## Follow-up: ID cards and Graphic Orders (fix392)

- ID-card drafts await the save result, retain their contents on failure, and reuse row IDs on retry. Text is captured on input; saves wait for photo preparation and photo callbacks retain the intended row. Authentication refresh does not rebuild an open draft.
- ID-card shared writes are sequenced; incomplete shared/legacy reads do not trigger migration writes. Shared records win equal-timestamp ties against legacy copies. Save messages distinguish durable acceptance from online confirmation.
- Orders freeze each dispatched queue token so a second edit cannot be removed by an older request completion. Pending operations on the same path prevent premature confirmation. Recent writes are protected from stale snapshots for two minutes, while newer remote records and explicit tombstones retain priority.
- Async asset completion updates the current local snapshot instead of restoring its earlier full array. Order forms remain open when queued or changed during save, and durable new orders become edits to avoid duplicate creation on retry. Successful saves reset stale list filters within existing viewer permissions.
- Validation: 96 tests passed, including five new behavioral regressions. Local browser test with synthetic data confirmed failed ID-card saves retain text and a successful retry creates one row. No production employee/card records were modified for testing. These checks do not certify every employee device or recover previously lost unsaved input.
